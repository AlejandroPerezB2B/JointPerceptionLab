# Joint Perception Lab v0.5 — biological-motion trial ordering

**Status:** Python implementation and automated sequence tests completed. Not yet tested on the target Windows computers. Shared visual-onset synchronisation and physical display timing remain unvalidated.

## Experimental design

The main experiment uses the 80 distinct conditions generated by: biological-motion signal (`U` intact/present, `S` scrambled/absent) × noise (24, 48, 96, 192) × direction (L, R) × position (-20, -10, 0, +10, +20). Each unique stimulus occurs once in **Block 1** and once in **Block 2**, for 160 main trials. Each block therefore has 40 present and 40 absent trials, 20 trials per noise level, and 10 trials for each signal × noise combination. A rest screen occurs after trial 80; both shared participants must press SPACE before Block 2 begins.

**Transition balancing:** For each block, the binary sequence of walker absent (0) and present (1) is constructed using a randomised Eulerian circuit with 20 occurrences each of 00, 01, 10 and 11 *when the sequence is interpreted cyclically*. The actual 80-trial linear sequence has only 79 adjacent pairs; the omitted final-to-first wraparound transition causes one pair to appear 19 times and the others 20 times. The transition from the end of Block 1 to the start of Block 2 is **not** included in the balancing constraint because there is a break. Noise, direction, and position are shuffled within each signal category and **their transition probabilities are not controlled**. This is constrained pseudorandomisation, not a full 80-symbol de Bruijn sequence. There is no immediate repeat of the same filename *within a block*; the last stimulus in Block 1 may equal the first stimulus in Block 2.

## Seeds and shared sessions

- **Individual:** a fresh 64-bit random seed is generated when the operator clicks Start experiment. It is stored in `data/<session>/session.json` under `config.main_seed`.
- **Shared:** both computers calculate the same 64-bit seed as the first eight bytes of SHA-256 of the UTF-8 string `JPL-v0.5-main:` followed by the stripped shared session label, interpreted as an unsigned big-endian integer. **Enter the same label on both computers and choose a NEW label for every new dyad.** Reusing a label reuses the same main order. The host/client handshake checks a SHA-256 digest of the ordered practice and main stimulus filenames and refuses to proceed if the lists differ.
- **Practice:** unchanged from v0.4: ten fixed-seed (`20260608`) trials, five walker-present and five absent, preferentially noise level 12.

## Recorded files

- `session.json`: full configuration, `main_seed`, and `order_quality` per-block transition and run-length diagnostics.
- `main_order.csv`: all 160 trials, including `block`, `block_trial`, `repetition`, stimulus metadata and filenames.
- `practice_order.csv`: practice sequence.
- `trials.csv`: completed responses, timings, and new `block` and `block_trial` columns.
- `frame_events.jsonl` and `timing_report.json`: software-side timing diagnostics from v0.4.

## Operator instructions (Windows)

1. Preserve your v0.4 folder. Extract this ZIP into a **new** folder, e.g. `C:\JointPerceptionLab_v05`. Open its inner `JointPerceptionLab` folder.
2. Copy the complete MP4 stimulus collection into `stimuli\biological_motion` (the ZIP contains only the example `S24L0.mp4`).
3. Run `setup_windows.bat` once in the new folder (Python 3.11 required), then run `run_windows.bat`.
4. **Individual:** choose Individual, enter participant ID, Validate stimuli, then Start experiment.
5. **Shared:** use a unique session label, e.g. `dyad_20261121_01`. On **Computer 1 (HOST)** select Shared — Host and click **Start experiment FIRST**. Wait while it listens. Only then, on **Computer 2 (CLIENT)** select Shared — Client, enter the host's real IPv4 address and the *same session label*, and click Start experiment. The host must be running before the client attempts to connect.
6. Both participants press SPACE when ready. They respond independently with Y or N. After trial 80 each presses SPACE to resume from the break. Press ESC to abort a test session; completed rows are retained.
7. Inspect `data/<session>/session.json` (`main_seed` and `order_quality`) and `main_order.csv` for the planned order. **For a dyad, verify the two `main_order.csv` files are identical in filename and order.**

## Important limitations

The v0.5 change addresses trial ordering, not cross-computer stimulus-onset synchronisation. The networking code still uses TCP barriers, not a common display clock. `order_digest` checks filenames and order, **not video-file contents**; ensure identical MP4 files on both computers. Display timing and synchronisation should be independently validated before collecting research data. The line-bisection module is not yet implemented.

## Automated checks

Run `python -m unittest discover -s tests -v` from the project folder in the installed Python environment. The new tests check exact factorial coverage, two-block uniqueness, balanced transitions across multiple seeds, reproducibility across input order, and invalid stimulus sets.
